# Customer Shopping Behavior Analysis (S3 -> PySpark -> PostgreSQL -> Power BI)

An end-to-end data engineering and analytics pipeline that ingests raw customer shopping data from **AWS S3**, cleans and transforms it using **PySpark**, loads the processed dataset into **PostgreSQL**, answers key business questions with **SQL**, and visualizes insights in **Power BI**.

> This project extends a standard local Pandas analytics workflow into a scalable, cloud-backed ETL pipeline using S3A and Apache Spark.

---

## Architecture

```text
+-------------+      +------------------+      +--------------+      +------------------+
|   AWS S3    | ---> |  PySpark ETL     | ---> |  PostgreSQL  | ---> |  SQL Analysis &  |
| (Raw CSV)   |      |  Clean / Enrich  |      |  (customer)  |      |  Power BI Report |
+-------------+      +------------------+      +--------------+      +------------------+
```

## ETL Pipeline Overview (`customer_behavior_etl.py`)

1. **Extract (AWS S3):**
   * Reads the raw CSV file directly from an S3 bucket using Hadoop's `S3AFileSystem`.
   * Applies an explicit `StructType` schema upfront to avoid an extra full scan from schema inference.
2. **Transform (PySpark):**
   * Standardizes all column names to `snake_case` and normalizes `purchase_amount_(usd)` to `purchase_amount`.
   * Deduplicates records by `customer_id`.
   * Imputes missing `review_rating` values using the per-category median (`percentile_approx` over a window partitioned by `category`), with a global median fallback.
   * Buckets `age` into four quartile-based `age_group` segments (`Young Adult`, `Adult`, `Middle-aged`, `Senior`).
   * Maps text values in `frequency_of_purchases` (e.g., `Weekly`, `Fortnightly`, `Quarterly`) into numeric `purchase_frequency_days`.
   * Dynamically checks whether `promo_code_used` is identical to `discount_applied` and drops it if redundant.
   * **Feature Engineering:** Adds `loyalty_tier` (`New`, `Returning`, `Loyal`, `VIP`), `estimated_annual_spend`, `is_high_value_subscriber`, and an `ingested_at` UTC timestamp.
3. **Data Quality Gate:**
   * Validates that the transformed dataset is non-empty, contains zero nulls in `customer_id` and `review_rating`, and flags any non-positive purchase amounts before writing.
4. **Load (PostgreSQL):**
   * Writes the cleaned DataFrame into the `customer` table using Spark JDBC with batching (`batchsize=10000`) and `truncate=true` on overwrite so downstream views and constraints remain intact.

## SQL Business Analysis (`customer_behavior_sql_queries.sql`)

Once the data is loaded into PostgreSQL, the SQL script answers 10 core business questions:

1. **Revenue by Gender:** Total revenue generated by male vs. female customers.
2. **High-Spending Discount Users:** Customers who used a discount yet still spent above the overall average purchase amount.
3. **Top-Rated Products:** Top 5 products with the highest average review rating.
4. **Shipping Type Comparison:** Average purchase amount for Standard vs. Express shipping.
5. **Subscription Impact:** Comparison of customer count, average spend, and total revenue between subscribers and non-subscribers.
6. **Discount-Heavy Products:** Top 5 products with the highest percentage of discounted purchases.
7. **Customer Segmentation:** Grouping customers into `New`, `Returning`, and `Loyal` segments based on previous purchases.
8. **Top Products per Category:** Top 3 most purchased items within each product category using `ROW_NUMBER()` window functions.
9. **Repeat Buyer Subscriptions:** Subscription breakdown among repeat buyers (more than 5 previous purchases).
10. **Revenue by Age Group:** Total revenue contribution across each age quartile.

## Getting Started

### Prerequisites
* Python 3.9+
* Java JDK 8, 11, or 17 (required by PySpark)
* PostgreSQL running locally or on a remote server
* An AWS S3 bucket containing `customer_shopping_behavior.csv`
* Power BI Desktop (to view/refresh the `.pbix` file)

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Configure Environment Variables
Create a `.env` file in the project root (make sure `.env` is listed in your `.gitignore`):

```env
AWS_ACCESS_KEY_ID=your_aws_access_key
AWS_SECRET_ACCESS_KEY=your_aws_secret_key
AWS_REGION=us-east-1
S3_BUCKET=your-s3-bucket-name
S3_KEY=raw/customer_shopping_behavior.csv
# S3_ENDPOINT=https://your-custom-s3-endpoint   # Optional (e.g., MinIO)

PG_HOST=localhost
PG_PORT=5432
PG_DATABASE=customer_behavior
PG_USER=postgres
PG_PASSWORD=your_postgres_password
PG_TABLE=customer
PG_WRITE_MODE=overwrite
```

### 3. Run the PySpark ETL Pipeline
Spark will automatically download the required S3A and PostgreSQL JDBC JARs at runtime:

```bash
spark-submit \
  --packages org.apache.hadoop:hadoop-aws:3.3.4,org.postgresql:postgresql:42.7.3 \
  customer_behavior_etl.py
```

### 4. Run SQL Analysis & Open Power BI
1. Execute the queries in `customer_behavior_sql_queries.sql` against your `customer_behavior` PostgreSQL database (via `psql`, pgAdmin, or DBeaver).
2. Open the `.pbix` file in Power BI Desktop, update the PostgreSQL data source credentials if needed, and click **Refresh**.
